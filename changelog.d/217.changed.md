- **Backup retention by epoch** (`backup.retention`, on by default; `rutli-cosigner backup-retain`). The backup sidecar deletes the archives of an older key epoch only when the newer epoch is proven (`keyfile prove`, from the previous change) and the proof is `backup.retention.minProofAgeDays` old (default 7); a complete verified archive of the proven epoch and the newest archive always remain. With no proof nothing is deleted by epoch. It deletes nothing when an archive's epoch cannot be read (v1 key files, a damaged tar), when this node's live epoch is behind its newest archive's (a node that missed a refresh), or on any error, and says why in the sidecar log (`BACKUP_RETENTION …`). `backup.destination.keep` still caps the number of archives but never takes the newest or the proven one. `backup-retain --dry-run` lists what it would delete. **Upgrade note:** the sidecar now mounts the cosigner's config read-only and runs the cosigner binary after each backup (the sidecar image must contain it, as the default does); the pod template changes, so roll the cosigners one at a time. Until `keyfile prove` has been run for a key's live epoch, its older archives stay (up to `keep`); the `RutliKeyEpochUnproven` alert says so after three days. Set `backup.retention.enabled=false` for the old count-only rotation. `docs/disaster-recovery.md`, "Backup retention".
